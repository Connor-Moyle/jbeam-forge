# JBeam Forge 0.16.0 test build 4: pickers that say when the game's parts are still being read

> **Test build.** 0.16.0 for testing before it goes out to everyone. It shows in the app only with Settings → Downloads → "Include pre-release (test) versions". Please report what breaks: [GitHub Issues](https://github.com/Connor-Moyle/jbeam-forge/issues).

## Downloads

- **JBeam-Forge-Setup-0.16.0-test.4.exe**: the installer. It updates any earlier version in place; your settings, projects and library stay.
- **JBeam-Forge-0.16.0-test.4-portable.exe**: a single exe, nothing to install.
- **jbeam-forge_0.16.0-test.4_amd64.deb**: Linux (Ubuntu, Mint, Pop!_OS…): `sudo apt install ./jbeam-forge_0.16.0-test.4_amd64.deb`.
- **JBeam-Forge-0.16.0-test.4.AppImage**: Linux, any distribution: make it executable and run it. The Linux version has not been tried on a real Linux PC with BeamNG yet.
- **jbeam_forge_ingame.zip**: JBeam Forge for inside the game, if you'd rather drop it in your mods folder by hand. The app installs and updates it for you (Settings → BeamNG.drive).

## Fixed since test build 3

- The first time it starts (and once after this update) JBeam Forge reads the parts of your BeamNG.drive install, which takes a few minutes. Until that was done, choosing a suspension, an engine or a gearbox showed an empty page with no word of why, and Choose suspension could do nothing at all. The pickers now say the game's parts are being read, fill in by themselves when it is done, and offer to read them again if nothing was found.

Everything else is as in [test build 3](https://github.com/Connor-Moyle/jbeam-forge/blob/main/docs/releases/v0.16.0-test.3.md), which lists what is new and the known problems. The full list of changes in 0.16 is in [v0.16.0.md](https://github.com/Connor-Moyle/jbeam-forge/blob/main/docs/releases/v0.16.0.md).
